# Shell cache log — web/shell/sw.js

Why this file exists: every reason the service-worker cache version was rolled used to live in a
**single 10.5 KB comment on line 3 of `sw.js`** — nearly half the file, unreadable in any diff and
shipped to every browser on every update check. The version constant stays in the code; the history
lives here.

**Rolling the cache**: bump `CACHE` in `web/shell/sw.js`, then add a row at the top of this table.
Roll it whenever a precached shell asset changes (JS/CSS/HTML/i18n) or the app registry must be re-read.

| `v130` | **the `/api/*` boundary closes for agent-written apps**. Until now every app ran in the SAME origin as the shell: the pairing cookie travelled on its fetches and it could call any route — an app that declared `storage.app` could read `/data/anima/teacher.json` and walk off with the keys. The service worker could do nothing about it: on the device the OS is served over http, which is not a secure context, so there the SW does not exist. Now apps with `created_by:'agent'` run with `sandbox="allow-scripts"` **without** `allow-same-origin` — an opaque origin, no cookie, no shared storage, `/api/*` unreachable — and reach the OS only through a `postMessage` broker that grants exactly what the manifest declared (confined `fs.read/write/list`, `notify`). The 46 curated apps are untouched. The scaffold templates are born against the broker, so there is no migration. RAM bonus: every brokered call goes through **one serial queue**, so N sandboxed apps cannot saturate the 4-6 sockets — the device works less than before. |
| `v129` | **semaphore and coalescing on `/api/anima`**. Twelve surfaces call that endpoint — copilot, the shell search, onboarding, `ai.js`, and the anima/agent/settings/spreadsheet/games/miei-fatti/recorder/code-runner apps — and none of them knows about the others: on a chip without PSRAM with 4-6 sockets, the "never concurrent calls" rule was left to the good manners of twelve files. Now they go through a **shared** slot (not an exclusive one: a `mode=on` query opens a TLS session and would freeze every file read), and IDENTICAL in-flight questions become **one single request** with the same answer for everyone. Zero extra bytes, less concurrency: a negative device cost. |
