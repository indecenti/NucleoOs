# Shell cache log — web/shell/sw.js

Why this file exists: every reason the service-worker cache version was rolled used to live in a
**single 10.5 KB comment on line 3 of `sw.js`** — nearly half the file, unreadable in any diff and
shipped to every browser on every update check. The version constant stays in the code; the history
lives here.

**Rolling the cache**: bump `CACHE` in `web/shell/sw.js`, then add a row at the top of this table.
Roll it whenever a precached shell asset changes (JS/CSS/HTML/i18n) or the app registry must be re-read.

| `v130` | **il confine `/api/*` si chiude per le app scritte dall'agente**. Finora ogni app girava nella STESSA origine della shell: il cookie di pairing viaggiava sulle sue fetch e poteva chiamare qualunque rotta — un'app che dichiarava `storage.app` poteva leggere `/data/anima/teacher.json` e portarsi via le chiavi. Il service worker non poteva farci nulla: sul device l'OS e' servito in http, che non e' secure context, quindi li' il SW non esiste. Ora le app con `created_by:'agent'` girano con `sandbox="allow-scripts"` **senza** `allow-same-origin` — origine opaca, niente cookie, niente storage condiviso, `/api/*` irraggiungibile — e arrivano all'OS solo attraverso un broker `postMessage` che concede esattamente cio' che il manifest ha dichiarato (`fs.read/write/list` confinati, `notify`). Le 46 app curate non sono toccate. I template dello scaffold nascono contro il broker, quindi non c'e' migrazione. Bonus RAM: ogni chiamata brokerata passa da **una coda seriale**, quindi N app sandboxate non possono saturare i 4-6 socket — il device lavora meno di prima. |
